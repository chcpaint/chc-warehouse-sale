Security and data protection

The short version for your IT team. Ask us for the full security write-up.

Encrypted in transit In place

Every page and every request uses HTTPS, and browsers are told to use HTTPS only.

Encrypted at rest In place

The database and stored files are encrypted on disk by our database host, Supabase.

Each customer kept separate In place

Our server checks every request against the signed-in company and location. One shop cannot read another shop's orders, stock or prices.

Passwords never stored In place

Only a one-way hash (bcrypt) is kept, so nobody, CHC included, can read a password. Reset links expire.

Sign-ins expire In place

Sessions end after 12 to 24 hours. Repeated failed sign-ins are slowed down and then blocked.

Browser protections In place

Strict security headers and a content security policy limit where code can load from. Search text is cleaned before it reaches the database.

Audit trail In place

Changes CHC staff make to customers, prices, users and settings are recorded with who, what and when. Stock movements record who made them.

Checked on every change In place

Each code change runs the full automated test suite and a scan for known vulnerabilities in the software it depends on.

Where your data lives In place

In the United States (US West), with Supabase for the database and Railway for the app.

Backups In place

The database is backed up automatically by Supabase.

Being put in place

Restore drills In progress

A scheduled test that restores a backup into a separate copy, to prove recovery works, and a decision on point-in-time recovery.

Two-step sign-in for CHC staff In progress

A second step at sign-in for the people who can see every customer.

Outside uptime monitoring In progress

An outside service that checks the console every minute and alerts us if it stops answering.
